UNIT 1

Classes, Objects, Arrays, Math and String methods

The building blocks used to represent exam data and calculate marks.

1. Classes and objects

A class is a blueprint; an object is an instance created from that blueprint. In this project, Question, Exam and Result can be represented as classes.

class Question {
    String text;
    String[] options;
    int correctOption;

    Question(String text, String[] options, int correctOption) {
        this.text = text;
        this.options = options;
        this.correctOption = correctOption;
    }
}
Question q1 = new Question("Java entry point?",
    new String[]{"start()", "run()", "main()", "init()"}, 2);

Project use: each question is stored as an object with its text, options and correct answer.

2. Arrays

An array stores a fixed number of values of the same data type. The selected answer for each question can be stored by question index.

int[] answers = {-1, 2, 0, 3};
// -1 = unanswered; 0, 1, 2, 3 = options A, B, C, D
answers[0] = 1;

Project use: keep student responses aligned with question positions for evaluation.

3. Math class

Java's built-in Math class performs mathematical operations. Use floating-point division to calculate percentage.

double percentage = total == 0 ? 0 : score * 100.0 / total;
long roundedPercentage = Math.round(percentage);
boolean passed = percentage >= 40.0;

Project use: calculate marks, percentage and pass/fail status.

4. String methods

  • trim() removes extra spaces at the beginning and end.
  • isBlank() checks empty or whitespace-only input.
  • equalsIgnoreCase() compares text without case sensitivity.
  • length() returns the number of characters.
  • toUpperCase() and toLowerCase() change letter case.
String username = enteredUsername.trim();
if (username.isBlank()) {
    System.out.println("Username is required");
}
boolean same = username.equalsIgnoreCase(savedUsername);

Project use: validate names/usernames and handle text consistently.

UNIT 2

Abstract class, Inheritance, Interface and Package

Object-oriented programming separates common user behaviour from role-specific behaviour.

1. Abstract class User

An abstract class is a base class that cannot be instantiated directly. It can hold common fields and define methods that child classes must implement.

abstract class User {
    protected String name;
    protected String username;

    User(String name, String username) {
        this.name = name;
        this.username = username;
    }
    public abstract void openDashboard();
}

2. Inheritance: Admin and Student

Inheritance allows a child class to reuse and specialize a parent class using extends. Admin manages questions; Student attempts exams.

class Admin extends User {
    Admin(String n, String u) { super(n, u); }
    @Override
    public void openDashboard() {
        System.out.println("Manage questions");
    }
}
class Student extends User {
    Student(String n, String u) { super(n, u); }
    @Override
    public void openDashboard() {
        System.out.println("Attempt examinations");
    }
}

Backend authorization must check the user's role too; hiding admin buttons in the interface is not sufficient security.

3. Interface Evaluable

An interface defines a contract. A class that implements it provides the required method.

interface Evaluable {
    int evaluate(int[] answers);
}
class Exam implements Evaluable {
    private int[] key;
    Exam(int[] key) { this.key = key; }

    public int evaluate(int[] answers) {
        int score = 0;
        for (int i = 0; i < key.length && i < answers.length; i++)
            if (answers[i] == key[i]) score++;
        return score;
    }
}

4. Package exam.core

A package groups related classes, prevents naming conflicts and improves organization. Example structure:

  • exam.core — Question, Exam, Result, evaluation logic.
  • exam.users — User, Admin, Student.
  • exam.ui — Login, admin and student screens.
  • exam.db — Database connection and DAO/repository classes.

The current repository instead uses com.group2.onlineexam, organized into model, service and web packages.

UNIT 3

Timer Thread, InvalidLoginException and synchronized

Concurrency and error handling help keep an examination reliable.

1. Timer thread

A thread is an independent path of execution. A countdown can run while a student answers questions and trigger submission at zero.

for (int remaining = 60; remaining >= 0; remaining--) {
    System.out.println("Seconds left: " + remaining);
    Thread.sleep(1000);
}

For Swing, update components on the Event Dispatch Thread using SwingUtilities.invokeLater or use javax.swing.Timer. For a web app, the server must enforce the exam deadline; a browser-only timer can be manipulated.

2. InvalidLoginException

A custom exception represents a specific application error. Throw it when credentials are invalid and catch it at the login screen.

class InvalidLoginException extends Exception {
    InvalidLoginException(String message) {
        super(message);
    }
}
if (!validCredentials) {
    throw new InvalidLoginException("Invalid username or password");
}

3. synchronized submission

synchronized restricts concurrent access to a critical section on the same object, helping avoid simultaneous modification of shared in-memory state.

public synchronized Result submitExam(String username, int[] answers) {
    // Validate, evaluate and store one submission.
    return createAndSaveResult(username, answers);
}

It does not replace database transactions, unique constraints or duplicate-submission checks across multiple application servers.

UNIT 4

JDBC, Statement, PreparedStatement and Database Tables

JDBC is Java's standard API for connecting to relational databases such as MySQL.

1. JDBC workflow

  1. Open a database connection.
  2. Prepare and execute SQL.
  3. Read rows from a ResultSet.
  4. Close resources.

2. Statement

Statement executes a fixed SQL query. Use it for SQL that does not contain user-supplied values.

String sql = "SELECT id, question_text FROM questions";
try (Statement st = connection.createStatement();
     ResultSet rs = st.executeQuery(sql)) {
    while (rs.next()) {
        System.out.println(rs.getString("question_text"));
    }
}

3. PreparedStatement

PreparedStatement uses ? placeholders and binds values separately. It is preferred for user input and helps prevent SQL injection.

String sql = "SELECT id FROM users WHERE username = ?";
try (PreparedStatement ps = connection.prepareStatement(sql)) {
    ps.setString(1, username);
    try (ResultSet rs = ps.executeQuery()) {
        if (rs.next()) System.out.println("User found");
    }
}

Example for storing a result:

String sql = "INSERT INTO results(username, score, total) VALUES (?, ?, ?)";
try (PreparedStatement ps = connection.prepareStatement(sql)) {
    ps.setString(1, username);
    ps.setInt(2, score);
    ps.setInt(3, total);
    ps.executeUpdate();
}

4. Suggested database tables

  • users: user_id, name, username, password_hash, role.
  • questions: question_id, question_text, option_a, option_b, option_c, option_d, correct_option, category.
  • results: result_id, user_id, score, total, percentage, submitted_at.

Use password hashes rather than plain-text passwords, foreign keys between results and users, and transactions for related writes.

Current code status: the GitHub main branch currently persists data in data/online-exam.dat using Java object serialization. JDBC, SQL tables, Statement and PreparedStatement are explained here but are not yet integrated into that branch.
UNIT 5

JRadioButton, JButton, JLabel, Layouts and ActionListener

These are Java Swing components used to build the desktop examination interface described in the project outline.

1. JRadioButton

Allows a student to select one option. Add the options to a ButtonGroup so only one can be selected.

JRadioButton a = new JRadioButton("Option A");
JRadioButton b = new JRadioButton("Option B");
JRadioButton c = new JRadioButton("Option C");
JRadioButton d = new JRadioButton("Option D");
ButtonGroup group = new ButtonGroup();
group.add(a); group.add(b); group.add(c); group.add(d);

2. JButton and JLabel

JButton creates clickable controls such as Login, Next and Submit. JLabel displays text such as the question, timer, student name or score.

JLabel question = new JLabel("Which is Java's entry method?");
JButton next = new JButton("Next");

3. GridLayout and FlowLayout

  • GridLayout arranges components in equal-sized rows and columns, useful for a question-number palette.
  • FlowLayout places components from left to right and wraps them, useful for navigation buttons.
JPanel palette = new JPanel(new GridLayout(0, 5, 8, 8));
JPanel controls = new JPanel(new FlowLayout(FlowLayout.RIGHT));

4. ActionListener

An ActionListener handles an action event, commonly a button click.

next.addActionListener(event -> {
    saveSelectedAnswer();
    showNextQuestion();
});

Typical actions: login, register, start exam, select an answer, navigate questions and submit.

Current code status: the GitHub main branch uses an HTML/CSS/JavaScript browser interface, not Swing. It does not currently use JRadioButton, JButton, JLabel, GridLayout, FlowLayout or Swing ActionListener.
